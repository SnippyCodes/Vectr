## 1. Problem Statement

Contributing to open source today is a broken, painful ordeal characterized by two opposing bottlenecks:
1. **The Contributor Bottleneck (Overcrowding & Friction):** Millions of CS students and aspiring engineers are told to "contribute to open source" to build their resumes and land jobs. In practice, they flock to the same 10 famous repositories (Next.js, LangChain, FreeCodeCamp), where their PRs sit unreviewed for months, or they spend 4+ hours fighting local build configurations and dependency mismatches before abandoning the effort.
2. **The Maintainer Bottleneck (The Spam Wave):** Maintainers of growing open-source projects are drowning in low-effort, AI-generated "slop" PRs, trivial typo fixes, and chaotic "assign me" comments, causing maintainer burnout and cynicism toward first-time contributors.

---

## 2. Demand Evidence & The Status Quo

### Demand Evidence
- **Founder's Direct Experience:** Extreme friction getting stuck with environment setup, dependency configurations, and discovering viable repositories.
- **Observable Market Behavior:** Thousands of students post on Reddit/X daily asking "How do I actually get my first PR merged?" while GitHub's `good-first-issue` labels are inundated within minutes by bots and spam comments.

### The Status Quo & Where It Fails
- **GitHub Search / Labels:** 90% of issues tagged `good-first-issue` are either claimed, outdated (from 2022), or deceptively difficult (requiring deep domain knowledge of 50k+ lines of code).
- **Local Dev Setup:** Contributors clone a project, run `npm install` or `poetry install`, hit missing system binaries/Node version mismatches, get frustrated, and quit.
- **GitHub Codespaces / Gitpod:** Heavy cloud development environments solve the machine setup, but offer **zero intelligence**—the user is still dropped into a massive codebase with no guidance on *what* to write, *where* to write it, or *how* to pass the repo's PR review guidelines.

---

## 3. Target User & Narrowest Wedge

### The Exact Human With Hair on Fire
- **The CS Student / Junior Engineer:** Needs 2–3 merged Pull Requests in reputable open-source projects on their public GitHub profile within the next 30 days to stand out in a brutal tech hiring market and pass technical resume screens.

### The Narrowest Wedge: The "In-Browser Fast-Track PR Engine"
To win immediately without burning through server costs or building a multi-million-dollar cloud VM infrastructure:
- **What it IS:** 
  1. **Opportunity De-congestion Algorithm:** Steers contributors away from overcrowded mega-repos toward active, 500–5,000 star repositories with responsive maintainers (<48hr PR review time).
  2. **Nova AI Issue Co-Pilot:** Analyzes the issue and points out the exact files, functions, and tests that need modification.
  3. **Zero-Compute In-Browser Code Editor:** An embedded Monaco code editor that fetches the relevant file directly via GitHub API, lets the user edit the fix in their browser, and commits directly to their fork via OAuth—**$0 server compute cost**.
  4. **AI PR Pre-Flight Auditor:** Audits the diff against the repository's `CONTRIBUTING.md`, style guides, and testing requirements before submission, giving an "Approval Confidence Score."
- **What it is NOT:** A heavy Docker-in-browser VM or cloud container host (which would bankrupt a bootstrapped founder on AWS credits).

```
            │ • Fetch issue & repo files  │                     │ • Nova AI (Gemini Flash)    │
            │ • Fork repo & commit diff   │                     │ • Repo opportunity scoring  │
            │ • Create Pull Request       │                     │ • Fast rate-limited cache   │
            │   (Zero server compute!)    │                     │ • PostgreSQL (Neon/Supabase)│
            └─────────────────────────────┘                     └─────────────────────────────┘
```

### Architectural Principles:
1. **Client-Side Execution Leverage:** Code editing and diff creation happen in the user's browser using Monaco Editor and direct GitHub API tokens. Vectr's backend never compiles or executes arbitrary code, preventing security breaches (crypto mining) and zeroing out infrastructure costs.
2. **Stateless AI Assistance:** Nova AI runs on Google Gemini 2.0 Flash (ultra-low latency, virtually free tier), providing instant contextual assistance for issues.
3. **Enterprise-Ready Data Schema:** Data model supports `User`, `Organization`, `Workspaces`, and `AuditLogs` from day one, allowing seamless expansion to B2B hiring.

## 6. Approaches Considered

### Approach A: Full Cloud VM Sandbox (Codespaces / Gitpod clone)
- **Concept:** Spin up an ephemeral Linux Docker container for every user on AWS EC2/Lightsail.
- **Why Ruled Out:** Destroys the $100 AWS credit runway in days, opens severe vulnerability to crypto-mining bots, and creates massive maintenance overhead for language runtimes.

### Approach B: Read-Only AI Summary Tool
- **Concept:** Just summarize issues and link back to GitHub.
- **Why Ruled Out:** Trivial "wrapper" value that does not solve the core pain of setup or getting code committed.

### Approach C (Recommended): In-Browser Git-Fork Editor + Opportunity Engine
- **Concept:** Client-side Monaco editor + GitHub API for commits + AI Pre-Flight Auditor + Repo De-congestion Algorithm.
- **Why Chosen:** Solves the entire contributor loop in one browser tab, costs $0 in compute execution, and provides real defensibility.
